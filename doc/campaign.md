# 引力破晓：堡垒战役设计与验证

## 重设计原则

全部 36 个新战役关卡重新编排，旧版 23 关保留原入口与布局。参考了旧版“轨道轰炸”的三角桁架与内部敌人、“陨石带”的多据点布置，以及重装堡垒和旗舰的分层结构。

新关从双层桁架、隔舱、凹面棱堡和连桥开始，再逐章加入真实泊车轨道、行星遮挡、整座堡垒运动、穿甲与特殊载荷、多处纵深据点。11 种建筑蓝图提供可复用构件；36 组位置、组合、轨道、弹药和文字提示均明确编排，不使用随机拼关。

内部控制单元藏在可碰撞的外墙后面，外墙质点和弹簧都实际参与模拟。普通外墙与控制单元不带连锁爆炸属性。前十关以有限弹药、分层外墙和成组内舱约束攻击；双塔关需要分别寻找接近两个塔舱的撞击面，其余关卡的目标数多于弹药数。满推力会消耗爆炸所需的燃料；对齐核心并不能越过外墙。通关没有另加硬性速度上限。

后期关卡从分开的塔舱、重装内环、双冠堡、十字船坞扩展到护卫与旗舰的组合；有些堡垒可以利用范围毁伤从薄弱侧清舱，有些航线更适合先用动能弹破壁。目标是让攻击位置、轨道相位与载荷分配影响结果，允许发现不同解法。

## 引导与进度

每关提供中文任务目标、操作说明和策略提示，六章首关有可跳过的中文战术简报。首关提供拖拽方向提示；瞄准时显示实际可用 Δv、点火后燃料，以及预计内舱清除范围。该范围是剩余爆炸半径的一半，不包含未来全部碎片碰撞。移动堡垒的轨迹预测包括参考框架平移，自由碎片变形仍是近似。

泊车轨道与堡垒、星体保持分离，避免未发射的弹体直接运行进墙内。新关飞行兜底为 30 秒，预测覆盖同一窗口，允许低推力进近；目标清除后仍使用 5 秒结果分析。所有关卡可直接选择。

重做关卡使用新的 `fortress-*` 存档 ID，原简单关卡的成绩不会误算为新关成绩，历史记录仍保留。旧关使用原 `legacyKey`。通关获得一星；在弹药标准内获得二星，再满足累计 Δv 标准获得三星。

## 验证方法

运行 `npm run check:campaign`，使用与游戏相同的 `LevelManager`、`Building`、`Bullet` 和 `FlightSimulation`。

- 回放 36 关的参考解，检查通关条件和有限数值；动作记录在 `campaign-solutions.json`，包括发射帧、弹体序号、Δv 和回放终点。
- 每关无操作模拟 1800 帧（30 秒）：全部构件、弹簧和目标保持存活，不产生分数；按秒检查泊车轨道不进入堡垒或星体。
- 将参考解的推力替换成全部燃料预算，检查前十关均无法过关。
- 前十关另进行满推力角度扫描：每度采样方向，对候选攻击进行实际回放，并按破坏结果选择后续攻击；有引力关卡分别从 0、3、6、9 秒出发。
- 回归检查缩放鼠标坐标、重试监听器销毁、燃料受限预测、爆心燃料预估、移动建筑锚点与未来外壳、精确弹簧中线接触、引力源中心、零燃料分裂、材料燃烧速率和旧存档映射。

角度扫描是有明确范围的反例测试，不是对任意角度、任意等待和任意多次机动的穷举证明。参考解证明关卡可解，不等同于每种打法都可行，也不替代玩家对难度与趣味性的反馈。验证报告 `campaign-validation.json` 保存关卡数据指纹、结构规模、参考解结果与满推力测试动作。

浏览器验证使用 `test/phase11-demo.html`，覆盖真实拖拽通关、满推力攻击失败、重试与中文简报，并检查大型移动堡垒的可读性和运行日志。

## 维护

`src/campaign-authoring.cjs` 是新战役的编排源，修改后运行 `npm run author:campaign` 生成 JSON。共用材料参数放在 `pointDefaults` / `springDefaults`，每条构件保留自己的坐标和连接关系。运行时加载 JSON，不执行生成器。

`src/campaign-solver.cjs` 的几何估计仅用于寻找候选动作；只有生产模拟回放通过的结果才进入参考解。修改物理、布局、弹药或目标条件后，重新验证参考解和反例；不要为了通过测试降低通关条件。所有关卡资源按章节分包，共用模拟和渲染入口。
